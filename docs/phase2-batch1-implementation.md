# 阶段 2 第一批实施记录

实施日期：2026-09-11

## 1. 本批目标

- 修正阶段 1 暴露的列表、代码块和公式误判。
- 聚合和压缩长文档质量报告。
- 增加 DOCX 渲染回读，输出真实页数变化和空白页。
- OCR 改为只识别 `ocr` 路由的具体页面，不再对整份 PDF 调用模型。

## 2. 结构识别修正

### 2.1 正文左边距

原实现使用页面最小 x0 作为正文左边距，章节标题的左侧位置会把普通正文全部判定为缩进。现在改为使用出现次数最多的行首位置作为典型正文左边距，并排除表格内文本行。

### 2.2 列表识别

- 显式项目符号、编号列表和具备相邻缩进上下文的缩进行才作为列表。
- 标题和代码行不参与缩进项目符号判断。
- 前 20 页样本中，普通正文从大量 `List Bullet` 恢复为 `Normal`。

### 2.3 标题识别

- `1.1`、`1.` 等数字标题必须位于正文左边界附近、文本较短、不以句号分号等结尾，并且字号明显大于正文或文本非常短。
- 增加 `第 N 章` 章节标题识别。
- 支持同一视觉行上的标题续行，减少标题后半部分被误判为列表。

### 2.4 代码块识别与导出

- 新增 C 语言代码特征判断：注释、预处理指令、大括号、分号、关键字、指针和寄存器表达式等。
- 连续代码行合并为一个代码块，保留原始换行和缩进。
- Word 导出新增 `Code Block` 段落样式，使用 Consolas 等宽字体。
- 代码赋值语句不再被识别为公式。

### 2.5 公式检测收紧

- 含 `{}`、`;` 的代码行不再进入公式路线。
- 只有包含数学符号、上下标、希腊字母，或简单数学等式模式的文本才判定为公式。
- `实验指导书.pdf` 的 `formula_count` 从 282 降到 151。

## 3. 质量报告压缩

- `quality_report(compact=True)` 在超过 200 页时启用。
- 页眉页脚等高频 info 警告按警告码、严重级别和消息聚合，输出 `pages` 范围和 `page_count`。
- 压缩模式下 `page_results` 只保留需要复核的页面。
- 质量报告新增 `code_count`。
- `实验指导书.pdf` 的 `result.json` 从约 642 KB 降到约 22 KB。
## 4. DOCX 渲染回读

新增 `src/docx_render_validation.py`：

- `render_docx_to_pdf()`：通过 Microsoft Word COM 无界面导出 PDF。
- `inspect_rendered_pdf()`：统计实际页数、页数差和空白页。
- `validate_docx_rendering()`：组合渲染和检查。

Worker 集成：

- 任务参数 `render_validation` 为 true 时执行渲染回读。
- 质量报告写入 `rendered_page_count`、`page_delta`、`blank_pages` 和 `render_validation`。
- 页数不一致或出现空白页时，追加 warning 和 `needs_review_pages`。
- 服务端配置：`PDF_SERVICE_RENDER_VALIDATION`、`PDF_SERVICE_RENDER_TIMEOUT_SECONDS`。

本机验证：前 20 页样本源 20 页，Word 渲染为 21 页，`page_delta = 1`，无空白页。说明 `page_delta` 现在可以发现真实的分页变化。

## 5. OCR 按页识别

- 对 `ocr` 路由的每一页：单独渲染为 JPEG，调用 OCR pipeline 处理该图片，结果只写入该页 IR，然后删除临时图片。
- `hybrid` 模式下复用 OCR 阶段的页面图片，不重复渲染。
- 无效 PDF 或无法渲染时，回退到原整份 PDF pipeline，保持原有超时和错误路径。
- 测试验证：只调用一次 OCR，输入是 OCR 页面图片，文本页不会被送入 OCR。
- 真实扫描样本验证：`novus_scanned_ocr_twin.pdf` 经按页 OCR 成功，单页总耗时约 39.8 秒（含模型加载），平均置信度约 0.9735，未产生复核页。

## 8. 当前边界

- 代码块识别仍是启发式规则，存在少量正文误判为代码、代码行漏判为正文的情况。
- 部分图题、说明性文字仍可能被识别为 `List Bullet`。
- 短数字项仍可能被识别为 `Heading 1`，需要更可靠的标题/列表模型或版面上下文。
- 页眉页脚过滤仍可能漏掉与图题、页码混合的页脚文本。
- 完整 898 页输出尚未执行 Word 渲染回读；当前只对前 20 页做了真实渲染验证。
- OCR 按页识别尚未在真实扫描 PDF 上做性能基准。
- `page_results` 压缩后，接口默认不再返回所有页的明细；如果需要逐页调试，需要增加单独的全量明细接口或导出文件。
