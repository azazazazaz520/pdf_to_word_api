# 路由文本判定重构方案：从码位区间到字符类别判据

编制日期：2026-09-13
适用范围：`D:\pdf_validation`（PDF 转 Word 独立验证项目）
状态：**已实施并验证**

本文承接 [下一阶段规划](next-phase-plan.md) 与 [当前讨论结论](current-discussion-results.md)。讨论结论第四节确立了通用原则："无法确认语义的异常字符仍应退回页面保真路线"。本文说明现行实现对这一原则的近似方式为何失效，以及替换方案。

## 2. 根因

### 2.1 判定源与执行源不是同一个抽取器

`src/pdf_routing.py` 是唯一使用 `pypdf` 抽取文本并据此判定的模块；版面提取（`src/layout/`）、渲染校验（`src/validate/`）与导出（`src/export/`）全部使用 `pypdfium2`。

样本字体为 `/Identity-H` 编码且**不含 `/ToUnicode`** 的 FandolSong、FandolKai：

```text
font /F7: Subtype=/Type0 BaseFont=/VPVIEB+FandolSong-Regular-Identity-H
          Encoding=/Identity-H ToUnicode=False
```

`pypdf` 在缺少 `/ToUnicode` 时按 CID 表回退解码，把 Adobe-GB1 的 CID 错映射成奥里亚文、泰卢固文、埃塞俄比亚文码位；`pypdfium2` 按字形名反查，抽取结果正常。同一页对照：

| 抽取器 | 字符数 | 命中"异常字形" | 文本头部 |
|---|---|---|---|
| `pypdf` | 82 | 5 | `RISC-V࠹\nR V32Eൌགྷᆷଲ` |
| `pypdfium2` | 125 | 0 | `Re：从零开始的 RISC-V 处理器设计 RV32E 实现指南` |

**文本层是完好的，"异常字形"是判定环节自身的解码伪影。** 执行路线本可正确处理这些页面，判定环节却据错误文本将其排除。

### 2.2 "异常字形"用固定码位区间定义

```python
_GARBLED_CHAR_RANGES = (
    (0x2E80, 0x2FFF),   # 康熙部首、CJK 部首
    (0x0B00, 0x0D7F),   # 奥里亚文、泰米尔文、泰卢固文、卡纳达文、马拉雅拉姆文
    (0x1200, 0x137F),   # 埃塞俄比亚文
    (0x1D400, 0x1D7FF), # 数学字母数字符号
    (0xFB00, 0xFB06),   # 拉丁连字
    (0xFFFD, 0xFFFD),
)
```

其中两项在语义上站不住：

- **`U+2E80–U+2FFF` 包含正常汉字。** RAG 样本被标记的 1371 个字符是康熙部首，例如 `⼀⽂⽤⽅⾃`（分别 187、98、89、84、74 次）。它们是标准兼容字符，NFKC 归一化后即 `一文用方自`，属于正常中文排版。该区间把"中文的一种合法写法"整体定义为异常。
- **`U+0B00–U+0D7F`、`U+1200–U+137F` 是正常文字系统。** 把整个奥里亚文或埃塞俄比亚文区块定义为异常，等于规定"这些语言的文件一律不可编辑"。

判据的定义方向反了：应当枚举**什么是异常**，现行实现枚举的是**什么不是常见中英文**。

### 2.3 手工补丁表是同一问题的症状

```python
_SPECIAL_FONT_CHAR_MAPPING = str.maketrans({
    "\u0b35": "₁",   # 奥里亚文 VA
    "\u0b36": "₂",   # 奥里亚文 SHA
    "\u1250": "⎧",   # 埃塞俄比亚文 QHA
    "\uf0b7": "•",
})
```

`\u0b35`、`\u0b36` 正是上述错映射产生的码位，被逐个手工修掉。这是按文件打补丁：换一个文件、换一批 CID，补丁表即失效（该样本 26 页共命中 492 个字符，三个映射远不足以覆盖）。

## 3. 方案

### 3.1 统一抽取器

路由的文本抽取改用 `pypdfium2`，与版面提取、渲染校验、导出保持一致。判定所依据的文本即后续真正要导出的文本，判定源与执行源不再分离。

页面图像信号的迁移已逐项核对，`pypdfium2` 可完整复现原判据：

| 信号 | `pypdf` | `pypdfium2` |
|---|---|---|
| 页尺寸 | `page.mediabox.width/height` | `page.get_size()` |
| 图像数量 | `len(page.images)` | `sum(1 for o in page.get_objects() if o.type == 3)` |
| 图像固有像素 | `Image.open(image.data)` | `item.get_px_size()` |

14 个样本前 6 页核对：图像对象数量**逐个样本完全一致**；扫描件 `ARDUINO程序设计基础.pdf`（296 页，每页 1 个图像对象、0 字符）在两套 API 下均判定为全页图像（5329920 像素）。切换不会丢失扫描件识别能力。

`pypdf` 依赖随之消失，`src/pdf_routing.py` 不再导入 `pypdf`、`PIL` 与 `BytesIO`。

### 3.2 异常字形改用字符类别判据

替换为与 `src/service/ocr_quality.py` 中 `_is_suspicious_character` 同族的定义：

```python
def _is_suspicious_character(character: str) -> bool:
    """判断字符是否为无法确认语义的异常字形。"""
    return character in {"\ufffd", "\u0000"} or unicodedata.category(character) == "Co"
```

即只把**替换字符、空字符、私有区字符**视为异常。这与讨论结论第四节的表述一致：异常指"无法确认语义"，而 Unicode 通用类别正是对语义确定性的标准刻画，不依赖对文档语种的假设。

**已实测否决的扩展**：把格式类 `Cf` 与控制类 `Cc` 一并计入后，14 个样本**全部每页命中**（`矛盾论.pdf` 单文件 16703 个），信号被完全淹没，无法用于区分。

判据能力对照（`pypdfium2` 抽取，命中字符数 / 命中页数）：

| 样本 | 判据 A 固定区间（现行） | 判据 B 字符类别（本方案） |
|---|---|---|
| 计算机组成原理课程实验_Verilog部分 | 0 / 0 | 0 / 0 |
| RAG 技术路线调研报告 | 0 / 0 | 0 / 0 |
| F103电路板-用户手册 | 0 / 0 | 42 / 6 |
| 矛盾论 | 0 / 0 | 0 / 0 |
| 其余 10 个样本 | 0 / 0 | 0 / 0 |

判据 B 对上述 17 个误判文件命中为 0，说明误判被消除；唯一命中的 F103 为真实私有区字符（见 3.3），说明判据仍有区分能力，未退化为恒假。

### 3.3 私有区字符按来源分类处理

F103 样本命中的 42 个字符全部来自符号字体：

```text
font /FXF7: /ABCDEF+Wingdings-Regular  Subtype=/Type0 ToUnicode=True
```

| 码位 | 次数 | 上下文 | 渲染确认的字形 | 映射目标 |
|---|---|---|---|---|
| `U+F06C` | 28 | `主控芯片：STM32`、`以太网：W5500` | 实心圆点 | `•`（U+2022） |
| `U+F071` | 14 | `检查 USB 线连接`、`跳帽位置 1` | 空心方块 | `❑`（U+2751） |

两个字形经逐字裁切渲染目视确认（`tmp/render_glyphs2.py`）：按字符索引取得外接矩形、高倍渲染后裁切，再以"裁切区是否含墨迹"排除空白框。渲染结果与上下文一致，均为列表项前导符号。

处理方式：把符号字体私有区映射并入**归一化**，作为明确的符号表存在；异常判据本身不为此放宽。映射后 F103 的异常字符数归零，不再触发任何异常扣分。

### 3.3.1 异常字符罚分改为按比例

原实现对"存在异常字符"与"异常比例超阈值"分别扣 0.35 与 0.25。固定罚分使 1500 字的页面出现 1 个未映射符号即降至 0.65，低于 0.75 阈值而整页转入页面图像路线。现改为按比例的单层扣分：

```python
if garbled_char_count:
    garbled_char_ratio = garbled_char_count / max(text_char_count, 1)
    quality_score -= 0.35 * min(1.0, garbled_char_ratio / garbled_char_ratio_threshold)
```

满额罚分点仍落在既有的 `garbled_char_ratio_threshold = 0.05` 上，未引入新的可调系数；封顶值维持 0.35，未按原两层之和调整为 0.6，因为该数值本身同样没有校准依据。

实测效果（构造样本，可读字符 144 个）：

| 异常字符数 | 字符总数 | 占比 | 罚分 | 分数 |
|---|---|---|---|---|
| 2 | 146 | 1.37% | 0.096 | 0.904 |
| 5 | 149 | 3.36% | 0.235 | 0.765 |
| 8 | 152 | 5.26% | 0.35（封顶） | 0.65 |
| 20 | 164 | 12.2% | 0.35（封顶） | 0.65 |

### 3.4 归一化按消费方分离

判定用文本与版面用文本对归一化的要求不同，二者由两个函数分别承担：

| 函数 | 消费方 | 归一化范围 |
|---|---|---|
| `normalize_page_text` | 版面文本（`src/layout/models.py`）、OCR 质量 | 仅数学字母做 NFKC，加符号字体映射 |
| `_read_page_text` | 路由判定 | 全部兼容字符做 NFKC，再加符号字体映射 |

分离的原因在实施中确认：把 NFKC 范围扩大到全部兼容字符会连带折叠全角标点（`，`→`,`、`：`→`:`），改变 `src/layout/text.py` 生成的 `PdfTextLine.text` 与后续行分组，使实验指导书前 20 页的行匹配数由 275 变为 278、`max_bbox_error` 由 13.45 变为 26.24、`mean_ssim` 由 0.9603 变为 0.9493。路线判定不需要改动这些指标，因此共享函数维持原范围。

康熙部首（`U+2E80–U+2FDF`）的折叠随之只作用于判定路径。版面文本仍保留原码位，导出物中的字符与 PDF 文本层一致；若后续需要把部首折叠进导出内容，应作为独立改动处理，并重新度量上述三项指标。

统一抽取器后，`\u0b35`、`\u0b36`、`\u1250` 不再出现，三个映射与其所在结构一并删除，只保留有明确符号语义的条目。

### 3.5 阈值暂不校准

`quality_score` 的权重（`0.55/0.45/0.35/0.25/0.15`）与高质量阈值 `0.75` 目前没有校准依据。本方案只修正判据的**定义**，不改动权重与阈值：判据修正后 14 个样本中 12 个结论不变，剩余 2 个由"全部不合格"变为"全部合格"，不存在需靠调阈值弥合的中间地带。阈值校准应等到样本量与真实渲染覆盖率、bbox 误差数据齐备后进行，与 [下一阶段规划](next-phase-plan.md) 第二节列出的保真度指标缺失问题一并处理。

### 4.1 自动化门与基线门

| 项目 | 结果 |
|---|---|
| `python -m unittest discover -s tests` | 85 个测试通过（35.2 秒） |
| `tmp/check_imports_dynamic.py` | 41 个模块，问题 0 个 |
| `tmp/check_names.py` | 可疑名字 0 个 |
| 实验指导书前 20 页关键保真度指标 | `matched_line_count=275`、`unmatched_line_count=18`、`max_bbox_error=13.451`、`ssim.mean_ssim=0.9603`、`ssim.min_ssim=0.8866`，与基线一致 |

第 3.4 节记录了一次未通过基线的中间实现：把 NFKC 范围扩大到全部兼容字符后，上述三项指标分别变为 278、26.237、0.9493。按消费方分离归一化职责后恢复一致。

### 4.2 规模门

纯扫描件数量不变，说明识别能力没有因判据放宽而退化。

两项指标的变化是本方案的预期结果，而非退化：

- **SSIM 下降**：整页贴图的 SSIM 天然接近 1，改为版面重建后像素级相似度必然下降。按既定验收口径（分区域与布局指标为主，SSIM 为参考值），应以可编辑页、字符覆盖率与匹配行数为准，三者全部大幅改善。
- **耗时上升**：文本路线的版面重建比直接贴图昂贵，且会触发整页兜底评估。对照组耗时反而下降，说明该差异来自路线本身而非代码开销。

### 4.4 遗留事项

康熙部首（`U+2E80–U+2FDF`）的折叠目前只作用于判定路径。版面文本保留原码位，导出物中的字符与 PDF 文本层一致。RAG 样本这类以康熙部首排版的文档，其导出内容仍使用部首码位；是否需要折叠进导出内容属于独立改动，须重新度量 4.1 节的三项指标后再定。

对 6 份外部真实 PDF 的转换测试与耗时数据见 [外部 PDF 转换测试报告](external-conversion-test-2026-09.md)，其中记录的导出环节缺陷（控制字符、APP14 JPEG）已修复，整页兜底评估耗时占比偏高与部分文档的 Word 渲染校验失败尚未处理。

## 5. 与既有方案的关系

本方案是 [下一阶段规划](next-phase-plan.md) 待办事项的重新排序，不改动其既定范围。原有三项待办中，本方案先做第一项（判据定义），推迟第三项（阈值校准），第二项（按文档语种调整判据）由字符类别判据直接取代——通用类别定义本身不依赖语种，无需判定"这是什么语言"。

保真度报告缺陷（`fidelity_auto_fallback_pages` 恒为 `None`、质量门禁不覆盖 SSIM/覆盖率/bbox）不在本方案范围内，仍按原规划处理。
