### 1.2 必须先处理的问题

**问题一：文本布局校验会静默失效，并产出"通过"的错误结论。**

`src/docx_render_validation.py` 的 `compare_text_layout`（第 552—721 行）以"整行文本完全相等，或公共前缀不少于 4 个字符"作为匹配条件。当源 PDF 的一行在导出时被拆成多个 `w:framePr` 段（F103 样本即为此类），渲染侧每个段各自成为一行，源行无法与任何候选行建立匹配，69 个源行全部进入 `unmatched_line_count`。

无匹配时该函数把中位数、p90、最大 bbox 误差与最大字号误差一律记为 `0.0`，并给出 `passes_bbox=true`；`_apply_fidelity_acceptance` 据此判定 `bbox_ok=true`、`text_layout_available=false`。也就是说，在这一类文档上，报告中的"文本位置中位数约 1pt"没有数据支撑，接口验收反而判为通过。

**问题二：质量门禁不覆盖保真度指标。**

`src/pdf_worker.py` 的 `_evaluate_quality_gate` 只检查渲染回读成功、`page_delta` 阈值与空白页。F103 运行中 `ssim_ok=false`、存在 2 个整页贴图页、文本布局无有效匹配，门禁仍返回 `status=passed`。门禁目前只能证明"页数没变、没有白页"，不能证明"内容对得上"。

**问题三：0.98 整页 SSIM 在图片密集页不可达。**

F103 两个整页无损 PNG 兜底页复检后 SSIM 为 0.9699 / 0.9745，损失来自 Word 导出 PDF 时对图片的重编码，与文本重建质量无关。把整页 SSIM 0.98 作为硬目标会导致两个后果：一是永远无法达标，二是自动兜底会把本可编辑的页面不断转成贴图页，与"提高可编辑性"的方向相反。

**问题四：`rebuild_confidence` 的方向被反转。**

该指标按面积加权（原生 1.0 / 图片兜底 0.8 / 跳过 0.0）。实测结果中，整页贴图的 page_image 页得 0.8，而内容全部原生重建、只是跳过了整页白色背景矩形的文本页只有 0.35—0.64。指标本意是"重建可信度"，实际输出的是"原生内容面积占比"，两者被混为一谈，且数值高低与可编辑性相反。

**问题五：实现与文档处于未提交状态。**

`main` 分支最后一次提交为 `5a19209`。此后 `src/` 下 11 个新模块、14 个测试文件、`docs/` 下 6 份新文档、整个 `tools/` 目录，以及 `pdf_worker.py`（53 KB）、`pdf_to_word_exporter.py`（123 KB）的全部改动都未提交；`docs/project-structure.md` 未反映新模块；README 第 121 行、第 195 行仍在描述已删除的 `flow` / `text` / `hybrid` 模式。

## 2. 已确定的验收口径

**决策：改为分区域指标 + 布局硬指标，整页 SSIM 降为参考值。**

不再以单一整页 SSIM 作为交付判据。判定拆成三层：

**第一层 结构一致性（硬性）**

- 渲染页数与有效源页数一致，`page_delta = 0`；
- 无意外空白页；
- 源空白页按 `intentional_blank_pages` 处理并在报告中显式列出。

**第二层 文本重建质量（硬性）**

- 行级 bbox 误差中位数 ≤ 1.0pt，p90 ≤ 2.0pt；
- 字号误差 ≤ 0.5pt；
- 字符 n-gram 覆盖率 ≥ 0.99；
- 文本行匹配率 ≥ 98%，匹配率低于阈值本身即判定为不达标（不得出现"零匹配即零误差"）。

**第三层 视觉参考（记录，不阻断）**

- 整页 SSIM 按页记录，作为趋势观察值，取代原先的阻断性阈值；
- 图像区域内嵌图片与渲染结果的区域 SSIM 单列，标注为"图片重编码损失"，不计入文本重建质量；
- 文本区域与图像区域分别报告，便于区分"文字没对准"与"图片被重编码"。

自动整页兜底的触发条件改为"第二阶段任一硬指标不达标"，而非"整页 SSIM 低于 0.80"。

## 3. 阶段任务

阶段顺序按依赖关系排列：A 产出可信指标，B、C 依赖 A 的数据，D 可在任意阶段并行。

### 阶段 A：让保真度可度量

1. **重写文本行匹配。** 源侧与渲染侧统一使用 `extract_text(extraction_mode="layout")`；匹配前做全半角、空白字符、行尾连字符的归一化；对"一行拆成多个 span 帧"的情况按基线与水平间距聚类合并后再匹配；把匹配率作为独立判据写入报告与验收结论。
2. **统一 SSIM 计算范围。** 恢复逐页全量对比作为默认口径；若耗时不可接受，改为"未兜底页以布局误差判定，兜底页必算 SSIM"，并保证报告中始终体现实际参与对比的页数与页码（当前 F103 报告中 `source_page_count=2` 容易与文档总页数混淆）。
3. **拆分区域误差。** 在 `compare_pdf_pages` 与报告层增加文本区域、图像区域的分区统计。
4. **重定义 `rebuild_confidence`。** 拆成"原生内容面积占比"与"重建可信度"两个字段，或改变权重使跳过整页白色背景不再惩罚文本页。
5. **门禁接入保真度。** `_evaluate_quality_gate` 增加字符覆盖率、文本行匹配率、行级 bbox 中位数与 p90 三项检查，未达标即 `failed`，并在报告中给出阈值与实际值。

阶段 A 出口条件：在实验指导书前 20 页、F103 24 页两个样本上，报告能给出可信的逐页布局误差分布，F103 样本不再出现"零匹配判定通过"。

### 阶段 B：收敛可编辑内容

1. **启用区域级贴图。** `IRPage.fallback_regions` 已带 `bbox` 与原因，用它们替换当前整页贴图路径，把不可编辑面积压到真正无法重建的区域。这是减少贴图页面积最直接的手段。
2. **定位 p90 / 最大误差超标的行。** 依据阶段 A 的误差分布，逐类处理旋转文本、制表符对齐、混排 run 与首行缩进导致的偏差。
3. **按新口径重新验收**两个真实样本与 898 页文档，记录贴图面积比例、可编辑行占比与新的误差分布。

阶段 B 出口条件：真实样本按新口径全部达标（结构 + 文本质量），整页贴图页比例下降，报告不再出现无依据的"通过"。

### 阶段 C：泛化与性能

1. **固定回归样本集与基准脚本。** 覆盖扫描件（无文本层）、双栏论文、复杂公式（分式/根式/求和）、旋转与横排页面、200 页以上长文档；每次运行输出可对比的指标表。
2. **补足已知泛化缺口。** 多栏检测在异常 CMap、字符盒缺失、复杂分栏下仍会退回单栏顺序；旋转页面文本框内行距由 Word 决定，残差大于 `framePr`。
3. **长文档性能。** 目标 900 页从约 8 分钟降至 5 分钟以内：并行 Word COM 渲染、兜底页之外跳过复检、字体标定缓存复用、SSIM 计算并行化。

### 阶段 D：整理与交付

1. **清理临时脚本。** `tmp/` 下约 200 个 `patch_*.py`、`fix_*.py`、诊断脚本为一次性产物，移出仓库；仍有价值的探针（字体偏移、区域 SSIM、矩阵缩放）固化为 `tools/` 工具或单元测试。
2. **补齐文档。** 更新 README（删除 `flow` / `text` / `hybrid` 描述、更新门禁与环境变量清单）、`docs/project-structure.md`（补 11 个新模块）、`docs/agent-handoff.md`（待办改为本文档章节引用）。
3. **分批提交。** 按 Conventional Commits 类型分批次组织：字体识别与嵌入、高保真导出与 OOXML 定位、渲染回读与质量报告、服务与文档。提交前确认各批次通过 `python -m unittest discover -s tests`。提交需经确认后执行。
4. **Prism 侧端到端回归（依赖 A 完成）。** 主工程 `feat/pdf-to-word-integration` 分支的 5 个文件停留在 2026-09-01，未对照当前 fidelity 服务联调。质量报告字段在阶段 A 之后才稳定，建议在阶段 A 出口后执行集成方案中的阶段三（真实服务回归、OCR 与压力验证）。
